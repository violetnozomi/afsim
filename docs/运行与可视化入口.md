```bash
AFSIM_SOURCE=/home/pyh/afsim/afsim2.9/afsim-2.9.0-kylin_v10_sp1_x86_64/swdev/src
AFSIM_BUILD=${AFSIM_SOURCE}/build-ubuntu24

NRM_SOURCE=/home/pyh/afsim/network_resource_manager
```

部署到甲方环境时，只需替换这些根路径，插件源码内部不应写死甲方目录。

## 第一次接入或 CMake 配置变化

```bash
cmake -S "${AFSIM_SOURCE}" -B "${AFSIM_BUILD}" \
  -DWSF_ADD_EXTENSION_PATH="${NRM_SOURCE}" \
  -DBUILD_WARLOCK_PLUGIN_NetworkResourceManager=TRUE
```

成功标志：

```text
Configuring wsf_network_resource_manager
Configuring WARLOCK Plugin NetworkResourceManager
```

## 日常编译

只编译本项目相关目标，不需要每次全量编译 AFSIM：

```bash
cmake --build "${AFSIM_BUILD}" \
  --target wsf_network_resource_manager NetworkResourceManager nrm_framework_types_test \
  -j 4
```

编译产物：

```text
${AFSIM_BUILD}/wsf_plugins/libwsf_network_resource_manager_*.so
${AFSIM_BUILD}/libNetworkResourceManager_*.so
${AFSIM_BUILD}/warlock_plugins/libNetworkResourceManager_*.so
```

最后一个文件是 Linux 开发运行用的自动暂存副本。

## 运行自动测试

```bash
cmake --build "${AFSIM_BUILD}" --target nrm_framework_types_test
"${AFSIM_BUILD}/nrm_framework_types_test"
```

成功标准：命令退出码为 `0`。当前 AFSIM 顶层构建没有启用 CTest 注册，因此不能以
`ctest` 显示 “No tests were found” 判断本测试是否通过。

## Warlock 可视化入口

Windows 远程调试优先使用项目已经配置的私有 VNC 会话，完整步骤见
[Windows远程调试.md](Windows远程调试.md)。

### 启动前环境

当前为源码开发构建，需要设置资源路径和第三方动态库路径：

```bash
export SOURCE_ROOT="${AFSIM_SOURCE}"
export RESOURCE_PATH="${AFSIM_RESOURCE_ROOT}"
export LD_LIBRARY_PATH="${AFSIM_BUILD}:\
${AFSIM_BUILD}/3rd_party/osg-3.6.3-x64-lnx/lib64:\
${AFSIM_BUILD}/3rd_party/osgEarth-2.10.1-x64-lnx/lib64:\
${AFSIM_BUILD}/3rd_party/gdal-3.3.2-x64-lnx/lib:\
${AFSIM_BUILD}/3rd_party/geos-3.5.1-x64-lnx/lib:\
${AFSIM_BUILD}/3rd_party/proj-8.1.1-x64-lnx/lib:\
${AFSIM_BUILD}/3rd_party/qt-5.12.11-x64-lnx/lib:\
${LD_LIBRARY_PATH}"
```

正式安装包通常已经配置运行路径，不应要求甲方手工维护这段开发环境变量。

### 启动 Warlock

```bash
"${AFSIM_BUILD}/warlock" \
  "${NRM_SOURCE}/test_mission/framework_smoke.txt"
```

### 打开面板

Warlock 启动后选择：

```text
View → Network Resource Manager
```

如果菜单中没有该项，依次检查：

1. `${AFSIM_BUILD}/warlock_plugins/` 中是否存在插件库。
2. Warlock 插件管理器中是否识别 `Network Resource Manager`。
3. CMake Cache 中
   `BUILD_WARLOCK_PLUGIN_NetworkResourceManager:BOOL=TRUE`。
4. 插件版本和 AFSIM/WKF 插件 API 编译器字符串是否一致。

当前面板显示：

| 字段 | 含义 |
| --- | --- |
| Version | 插件版本 |
| Runtime state | 仿真初始化、运行、完成状态 |
| Simulation time | 当前仿真时间 |
| Networks | AFSIM 通信网络数量 |
| Endpoints | 通信端点数量 |
| Transmitted | 消息发送累计数 |
| Received | 消息接收累计数 |
| Message hops | 消息逐跳转发累计数 |

## 当前已知限制

现有 Warlock 开发运行环境在插件完成实例化后仍可能出现基线 `buffer overflow`。禁用本插件后
使用相同环境可以复现，因此不是本插件引入。当前已经验证：

- WSF 插件加载和命令行场景运行完成；
- Warlock 动态库加载成功；
- Warlock 插件管理器实际调用插件构造函数。

修复现有 Warlock 开发运行目录后，需要补做面板打开、仿真运行、数据刷新和正常退出验证。
