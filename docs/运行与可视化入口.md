只编译本项目相关目标，不需要每次全量编译 AFSIM：

```bash

  --target wsf_network_resource_manager NetworkResourceManager \
           nrm_framework_types_test nrm_snapshot_reporter_test \
           nrm_assessment_evaluator_test nrm_tests \
```


## 一键内部预验收

需要同时验证代码门禁、21项固定测试、八个批准场景和Warlock最终快照时，运行：

```bash
cd /home/pyh/afsim/network_resource_manager
./scripts/run_preacceptance.sh
```

脚本会按固定顺序执行：

1. 环境命令预检；
2. `ai_guard.sh static`与`ai_guard.sh test`；
3. 框架冒烟、四网总览、链路中断、拥塞、质量下降、通信能力、环境气象和导航误差八个场景，每个只运行一次；
4. 重启既有`nrm-warlock.service`一次并等待新的120秒最终快照；
5. 核对4个网络、10个端点、8条链路、8发送、8接收、0丢弃和0路由失败；
6. 生成Markdown报告、逐项日志和精简GUI快照证据。
7. 原子更新`output/preacceptance/latest_status.json`，供Warlock只读页自动显示。

结果目录为：

```text
output/preacceptance/<UTC时间戳>-<进程号>/
├── PREACCEPTANCE_REPORT.md
├── gui_snapshot_summary.json
├── results.tsv
└── logs/
```

同级`output/preacceptance/latest_status.json`采用
`nrm.preacceptance_status.v1`契约。脚本启动时写入`RUNNING`，结束后更新为`PASS`或
`FAIL`；该文件不是甲方正式接口。

任一检查失败时脚本返回非零退出码，但仍生成报告和已经取得的日志。该命令属于内部
`PRE_ACCEPTANCE`，不会把演示剖面提升为甲方最终验收，也不会修改systemd服务文件、AFSIM
核心或自动控制网络。

### 打开面板

面板默认显示。如果被关闭，选择：

```text
View → 网络资源管理器
```

如果菜单中没有该项，依次检查：

1. `${AFSIM_BUILD}/warlock_plugins/` 中是否存在插件库。
2. Warlock 插件管理器中是否识别`网络资源管理器`。
3. CMake Cache 中
   `BUILD_WARLOCK_PLUGIN_NetworkResourceManager:BOOL=TRUE`。
4. 插件版本和 AFSIM/WKF 插件 API 编译器字符串是否一致。

当前面板显示：

评估页默认打开，源节点和目的节点均通过下拉框选择。节点项显示平台名、网络类型和通信

“预验收状态”页没有执行按钮。它在独立工作线程中约每2秒读取一次小型状态文件，GUI只
接收解析后的值对象；仿真回调不执行文件I/O。验收命令会重启Warlock一次，因此VNC画面
短暂关闭后重新出现属于预期行为。

## 当前已知限制

- 当前四网为资源管理演示模型，不是完整协议栈。
- RSSI、SNR、BER和带宽只在通信结果满足有效条件时显示；通用网络显示`—`。
- 路由和链路来自`GLOBAL_TRUTH`全局通信图。
- PDR尚未实现组播预期接收者展开与重传去重。
- ACK、RTT和抖动尚未实现；排队与传输时延已输出平均值、P50和P95。
- 候选链路参数是演示近似值，标记为低置信度；尚未接入甲方四网模块输入。
- 已实现有界 K 条简单路径与有向边不重合备路；显式跨网网关尚未实现。
- 当前规划格式为内部`NRM_NETWORK_PLAN_V1`；甲方格式、专用规则和真实分发协议未提供。
- 本地分发包不下发到网络，也不自动建链、改频、分配时隙或修改路由。
- 需求建议只从显式有限候选中筛选，不自动应用，也不推导甲方未提供的资源规则。
- 模型服务当前仅为进程内强类型边界；甲方封装协议、真实网络服务和第三方参考模块未提供。
- headless mission没有可取得Warlock Facade和强类型快照的安全入口，未创建伪服务smoke。

完整操作见[功能使用手册](功能使用手册.md)，完成状态见
[实施状态与需求追踪](IMPLEMENTATION_STATUS.md)。
