## 路径约定

```bash
AFSIM_SOURCE=/home/pyh/afsim/afsim2.9/afsim-2.9.0-kylin_v10_sp1_x86_64/swdev/src
AFSIM_BUILD=${AFSIM_SOURCE}/build-ubuntu24

```

部署到甲方环境时，只需替换这些根路径，插件源码内部不应写死甲方目录。

## 第一次接入或 CMake 配置变化

```bash
cmake -S "${AFSIM_SOURCE}" -B "${AFSIM_BUILD}" \
  -DWSF_ADD_EXTENSION_PATH="${NRM_SOURCE}" \
  -DBUILD_WARLOCK_PLUGIN_NetworkResourceManager=TRUE
```

成功标志：

```text
Configuring wsf_network_resource_manager
Configuring WARLOCK Plugin NetworkResourceManager
```

## 日常编译

只编译本项目相关目标，不需要每次全量编译 AFSIM：

```bash
cmake --build "${AFSIM_BUILD}" \
  --target wsf_network_resource_manager NetworkResourceManager \
           nrm_framework_types_test nrm_snapshot_reporter_test \
           nrm_assessment_evaluator_test nrm_tests \
  -j 4
```

编译产物：

```text
${AFSIM_BUILD}/wsf_plugins/libwsf_network_resource_manager_*.so
${AFSIM_BUILD}/libNetworkResourceManager_*.so
${AFSIM_BUILD}/warlock_plugins/libNetworkResourceManager_*.so
```

最后一个文件是 Linux 开发运行用的自动暂存副本。

### 启动前环境

当前为源码开发构建，需要设置资源路径和第三方动态库路径：

```bash
export SOURCE_ROOT="${AFSIM_SOURCE}"

export LD_LIBRARY_PATH="${AFSIM_BUILD}:\
${AFSIM_BUILD}/3rd_party/osg-3.6.3-x64-lnx/lib64:\
${AFSIM_BUILD}/3rd_party/osgEarth-2.10.1-x64-lnx/lib64:\

${AFSIM_BUILD}/3rd_party/geos-3.5.1-x64-lnx/lib:\

```

正式安装包通常已经配置运行路径，不应要求甲方手工维护这段开发环境变量。

### 启动 Warlock

```bash
systemctl --user restart nrm-warlock.service
```

### 打开面板

面板默认显示。如果被关闭，选择：

```text
View → Network Resource Manager
```

如果菜单中没有该项，依次检查：

1. `${AFSIM_BUILD}/warlock_plugins/` 中是否存在插件库。
2. Warlock 插件管理器中是否识别 `Network Resource Manager`。
3. CMake Cache 中
   `BUILD_WARLOCK_PLUGIN_NetworkResourceManager:BOOL=TRUE`。
4. 插件版本和 AFSIM/WKF 插件 API 编译器字符串是否一致。

当前面板显示：

| 字段 | 含义 |
| --- | --- |
| Version | 插件版本 |
| Runtime state | 仿真初始化、运行、完成状态 |
| Reporting | `OK` 或可诊断的写入/队列错误状态 |
| Simulation time | 当前仿真时间 |
| Networks | AFSIM 通信网络数量 |
| Endpoints | 通信端点数量 |
| Transmitted | 消息发送累计数 |
| Received | 消息接收累计数 |
| Message hops | 消息逐跳转发累计数 |
| Four-network overview | 四网成员、链路和消息汇总 |
| Window metrics | 1秒、10秒、60秒吞吐、PDR、在线率和时延 |
| Members | 平台、设备、地址、状态和位置 |
| Links | 有向链路、距离、10秒吞吐、条件带宽/利用率和RF字段 |
| Task assessment | 当前/候选图可达性、主备路由、裕量、原因码和只读建议 |
| 通信能力 | 距离、速率、丢包率、时延、吞吐量、接入率及数据质量 |
| 资源规划 | 规划元数据、allocation/demand编辑、校验、只读推演和本地分发包 |
| 需求匹配 | 需求修订、批量状态、逐项差距和六类只读建议 |

评估页默认打开，源节点和目的节点均通过下拉框选择。节点项显示平台名、网络类型和通信
地址，列表随 AFSIM 快照刷新并保留仍有效的用户选择。

### 查看中央作战通信态势

启动后，窗口中央的 `AFSIM Operational Network View` 直接使用 AFSIM 仿真快照绘制，
不是脱离仿真的预置动画。

| 图形或线条 | 对象 |
| --- | --- |
| 三角形 | 作战飞机、CDL 载机 |
| 方形 | 指挥所、控制站、地面站 |
| 菱形 | 卫星和卫通终端 |
| 蓝色虚线 | Link-11 |
| 红色实线 | Link-16 |
| 紫色点线 | 卫通 |
| 绿色粗实线 | CDL |
| 黄色粗叠加线 | 评估主路由 |
| 青色叠加线 | 评估备选路由 |
| 路由虚线 | 路由包含尚未建立的参数化候选边 |
| 绿色/橙色圆环 | 任务源节点/目的节点 |

中央区标题下方显示 `snapshot version` 和 `T=仿真时间`。飞机位置随 AFSIM
`WSF_AIR_MOVER` 航路更新；链路端点、类型和状态来自当前通信网络快照。

默认场景包含蓝方通信飞机、指挥节点、两架红方战斗机、Link-11 控制站和成员、
卫通终端与卫星、CDL 载机与地面站，以及四类网络的周期通信。

> ⚠️ **当前兼容边界：** 标准 `MapDisplay` 三维地形插件在当前 AFSIM 2.9
> 二进制与远程 VNC 软件渲染组合下会在地形着色初始化阶段终止，因此 `0.5.0`
> 默认使用真实 AFSIM 数据驱动的二维态势图；三维地形底图列为后续独立兼容项。

## 当前已知限制

- 当前四网为资源管理演示模型，不是完整协议栈。
- RSSI、SNR、BER和带宽只在通信结果满足有效条件时显示；通用网络显示`—`。
- 路由和链路来自`GLOBAL_TRUTH`全局通信图。
- PDR尚未实现组播预期接收者展开与重传去重。
- ACK、RTT和抖动尚未实现；排队与传输时延已输出平均值、P50和P95。
- 候选链路参数是演示近似值，标记为低置信度；尚未接入甲方四网模块输入。
- 已实现有界 K 条简单路径与有向边不重合备路；显式跨网网关尚未实现。
- 当前规划格式为内部`NRM_NETWORK_PLAN_V1`；甲方格式、专用规则和真实分发协议未提供。
- 本地分发包不下发到网络，也不自动建链、改频、分配时隙或修改路由。
- 需求建议只从显式有限候选中筛选，不自动应用，也不推导甲方未提供的资源规则。

完整操作见[功能使用手册](功能使用手册.md)，完成状态见
[实施状态与需求追踪](IMPLEMENTATION_STATUS.md)。
