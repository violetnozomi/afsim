# 网络资源采集与四网总览

_功能版本 0.3.0 · AFSIM内部监听与指标闭环 · 最后验证：2026-07-30_

---

## 📋 功能目标

本功能从AFSIM仿真线程复制通信资源状态，通过Warlock事件桥交给GUI线程，并由独立文件
线程写出JSONL和CSV。它回答“当前有哪些网络、成员和链路，以及发生了多少通信事件”。

本版本不回答任务能否完成，也不把参数化演示值解释为真实装备指标。

## 🧱 数据对象

| 对象 | 已实现字段 | 后续字段 |
| --- | --- | --- |
| `NetworkSnapshot` | 名称、类型、模型、成员、在线数、链路、消息和三档窗口 | 频段、总容量 |
| `EndpointSnapshot` | 平台、设备、地址、状态、收发能力和位置 | 在线率、频率、队列 |
| `LinkSnapshot` | 源、目的、状态、距离、有效RF结果和窗口 | 建链时间 |
| `MessageStatistics` | 排队、发送、接收、跳、丢弃和路由失败 | 业务分类 |
| `MetricValue<T>` | 值、单位、有效性、来源、置信度和时间 | 样本数量 |

输入边界由`InputProvider`定义：

- `AFSIM_INTERNAL`：当前已实现
- `CUSTOMER_MODULE`：为甲方Link-11/Link-16等模块预留
- `REPLAY`：为JSONL离线回放预留

## 🔌 监听接口

当前使用的观察回调：

| 回调 | 用途 |
| --- | --- |
| `MessageQueued` | 排队次数、最近队列深度和关联起点 |
| `MessageTransmitted` | 发送计数、比特数和排队时延 |
| `MessageReceived` | 每跳接收/RF观测；地址匹配时记录最终目的端业务交付 |
| `MessageHop` | 实际逐跳计数 |
| `MessageDiscarded` | 丢弃计数 |
| `MessageFailedRouting` | 路由失败计数 |

网络、成员和链路每0.5秒从同一仿真时刻重建，避免GUI拼接不同版本。链路使用
`NetworkManager::GetGraph()`，因此界面语义为`GLOBAL_TRUTH`。

## 🖥️ 界面说明

### Four-network overview

每行一个网络，列出类型、名称、模型、成员、在线数、活动链路、发送、接收和失败数。网络
类型同时使用文字和颜色：

| 网络 | 颜色 |
| --- | --- |
| Link-11 | 蓝色 |
| Link-16 | 红色 |
| 卫通 | 紫色 |
| CDL | 绿色 |

### Members

展示平台、通信设备、地址、当前状态和经纬高。端点状态规则：

1. 设备损坏：`FAILED`
2. 设备关闭：`DISABLED`
3. 非工作状态：`OFFLINE`
4. 其余：`ONLINE`

### Links

展示有向边、启用状态、三维直线距离、带宽、10秒交付吞吐量、利用率以及RSSI、SNR和
BER。当前通用场景没有可靠RF结果，因此带宽、利用率和RF字段显示`—`。

### Window metrics

展示每个网络的1秒、10秒和60秒吞吐量、PDR、在线率、平均排队时延和平均传输时延。
详细口径见[通信窗口指标](通信窗口指标.md)。

## 📄 输出契约

JSONL schema为`nrm.snapshot.v2`，一行对应一个完整快照。核心字段：

```json
{
  "schema": "nrm.snapshot.v2",
  "snapshot_version": 10,
  "sim_time": 4.25,
  "provider_id": "afsim-internal",
  "network_count": 4,
  "endpoint_count": 8,
  "link_count": 8,
  "networks": [],
  "endpoints": [],
  "links": []
}
```

距离字段示例：

```json
{
  "distance_m": {
    "value": 9123.4,
    "valid": true,
    "source": "DERIVED",
    "confidence": "HIGH"
  }
}
```

输出线程队列最多保存128份待写快照；达到上限时丢弃最旧快照，仿真和GUI线程不等待磁盘。

## ✅ 验证证据

当前四网场景实际结果：

| 项目 | 结果 |
| --- | ---: |
| 识别网络 | 4 |
| 端点 | 8 |
| 有向链路 | 8 |
| 发送消息 | 4 |
| 接收消息 | 4 |
| 丢弃/路由失败 | 0/0 |
| 仿真结束时间 | 6 s |

已验证：

- `mission`解析、初始化和运行成功
- 四个目的端均收到对应消息
- Warlock持续运行且面板默认可见
- JSONL和CSV生成非空文件
- 数据契约与分类单元测试通过
- 上报线程停止时能排空队列

## ⚠️ 已知限制

- 初始化快照可能短暂显示成员未在线，下一周期会进入在线状态
- 累计消息保留在总览，窗口消息和派生指标显示在`Window metrics`
- 通用网络直连消息可能没有`MessageHop`事件
- 当前CSV只保存网络级汇总，端点和链路完整信息保存在JSONL
- 甲方外部输入和回放只完成接口边界，尚未实现具体提供者
