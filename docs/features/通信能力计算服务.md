# 通信能力计算服务

## 范围

v0.8 第一阶段提供纯 C++ `CommunicationCapabilityService`。输入为不可变
`ResourceSnapshot`、`CapabilityRequest`和可选`EnvironmentContext`，输出
`CapabilityResult`。服务不依赖 Qt/AFSIM，不自动建链、改频、分配时隙或修改路由。

## 路径复用

能力请求映射到`AssessmentTask`，由`AssessmentEvaluator`复用
`NetworkProfileRepository`和`ConstrainedPathSelector`完成当前图优先、候选图回退及
有界 K 路径选择。`CapabilityResult`消费所选路径，不建立第二套路径算法。

## 固定指标

| 指标 | 口径 | 缺失行为 |
| --- | --- | --- |
| `communicationDistanceM` | 各跳三维距离之和 | 任一跳距离缺失则无效 |
| `maximumHopDistanceM` | 所选路径最大单跳三维距离 | 任一跳距离缺失则无效 |
| `transmissionRateBps` | 路径瓶颈可准入容量 | 当前链路无观测容量则无效 |
| `packetLossPercent` | `100 - path PDR` | PDR分母不可靠则无效 |
| `transmissionDelayMs` | 当前链路传输时延或候选建链/传播时延逐跳累计 | 数据缺失则无效 |
| `networkThroughputBps` | 所选当前路径各跳10秒交付吞吐量的瓶颈值 | 无观测或含候选跳则无效 |
| `accessRatioPercent` | 所选路径目标网络在线成员数/成员总数 | 分母为零则无效 |

所有指标使用`MetricValue<double>`，携带`valid`、`unit`、`origin`、`confidence`、
`sampleTime`、`window`和固定`reason`。当前链路使用快照观测值；候选链路的容量、PDR和
建链时延只使用版本化剖面并标记`PARAMETERIZED_MODEL/LOW`。

## 环境边界

`EnvironmentEffectAdapter`按`TERRAIN`、`WEATHER`、`CELESTIAL`和
`ELECTROMAGNETIC_INTERFERENCE`返回独立效果。适配器接收能力请求、不可变快照、所选
端点路径和环境上下文。每项效果使用固定字段`pathLossDeltaDb`、`capacityScale`、
`packetLossDeltaPercent`和`delayDeltaMs`，字段继续携带有效性、来源、置信度、单位和原因码。
默认没有甲方数据时，四项均输出：

```text
valid=false
reason=ENVIRONMENT_DATA_UNAVAILABLE
```

第一阶段只规范化并输出适配结果，不猜测甲方数据结构，不内置天气数据，不实现传播衰减
公式，也不把环境效果应用到路径指标。

## 输出

Warlock“通信能力”页显示六项合同指标、最大单跳距离、路径来源、数据来源、置信度和原因
码。每次查询通过Reporter异步写入当前runId目录的`capability_results.jsonl`，schema为
`nrm.capability.v1`。

## 验证边界

`nrm_communication_capability_service_test`覆盖当前路径、候选路径、当前路径缺失时延、输入
置信度传播、环境适配器及所选路径、无路径、离线端点、零成员、缺失环境、NaN/Inf、无
吞吐观测和输入快照不可变。Reporter测试覆盖环境效果固定字段的JSONL序列化。
`capability_service_smoke`仅验证插件、当前图和消息交付底座。内部剖面和固定场景结果仅为
`PRE_ACCEPTANCE`。
