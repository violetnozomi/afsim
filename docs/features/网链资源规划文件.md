# 网链资源规划文件

## 1. 适用范围

`NRM_NETWORK_PLAN_V1`是Network Resource Manager用于v0.9第一阶段开发、测试和内部
预验收的严格文本格式，对应公共schema `nrm.network_plan.v1`。它不是甲方规划文件格式，
也不定义真实分发协议、频率保护规则、时隙复用规则或自动网络控制语义。

外部规划格式只能通过`NetworkPlanAdapter`转换为公共值对象。甲方格式、字段、字节序和
协议未提供前，不得从本格式反推或猜测甲方接口。

### 可直接加载的测试文件

| 文件 | 规模 | 用途 |
| --- | --- | --- |
| `data/network_plans/four_network_demo-r1.nrm` | 4个资源分配、4项需求 | 快速加载和基础界面检查 |
| `data/network_plans/operational_25node_complex-r1.nrm` | 25个平台、8个资源分配、12项并发需求、2项动态变更 | 综合资源规划演示 |

复杂规划对应`test_mission/operational_strike_demo/main.txt`，包含Link-11南北子网、Link-16
主用/保障子网、卫通主备波束和CDL主备高速资源池。文件中的25个平台均为协同平台，不含
敌方、武器或交战元素。

资源规划页针对小屏分为“资源分配、业务需求、校验问题、推演结果”四个二级页签。页面
顶部的加载、校验和只读推演按钮始终保留；点击校验后自动进入“校验问题”，点击只读推演
后自动进入“推演结果”。推演结果表按需求显示状态、并发结果、冲突任务、路径来源、速率、
时延、丢包率和原因码。

演示规划可以在同目录增加`<规划文件名>.scenario`绑定一行项目内场景路径。加载此类规划
时，插件比较当前mission：一致则直接加载；不一致则正常退出当前Warlock，由受控切换脚本
启动绑定场景，并通过`NRM_AUTO_PLAN_FILE`自动恢复规划和打开“资源规划”页。没有sidecar
的甲方规划不会切换场景。当前复杂样例绑定：

```text
data/network_plans/operational_25node_complex-r1.nrm.scenario
→ test_mission/operational_strike_demo/main.txt
```

该机制重启整个仿真，不在运行中删除或替换AFSIM平台，避免旧事件、链路和对象引用污染
新规划推演。

## 2. 词法规则

- 文件使用UTF-8或ASCII文本，每条记录占一行；
- 空行和首个非空白字符为`#`的整行注释可忽略；
- 所有字符串使用`std::quoted`兼容的双引号形式；
- 枚举、整数、浮点数和布尔值不得加引号；
- 布尔值只能写为`0`或`1`；
- 浮点数必须有限，不接受`NaN`、`Inf`或`-Inf`；
- 每行规定字段后不得存在尾随token；
- 未知magic、未知记录类型或未知枚举值均拒绝整个文件。

## 3. 完整文法

首个非注释记录必须且只能是头记录：

```text
NRM_NETWORK_PLAN_V1 "planId" revision "configVersion" "providerId" \
  "createdTimeUtc" STATE ORIGIN CONFIDENCE valid \
  "previousPlanId" previousRevision
```

其中：

- `revision`和`previousRevision`为无符号整数；
- `STATE`为`DRAFT`、`VALIDATED`、`REJECTED`或`READY_FOR_DISTRIBUTION`；
- `ORIGIN`为`AFSIM_INTERNAL`、`CUSTOMER_MODULE`、`REPLAY`、
  `PARAMETERIZED_MODEL`、`ESTIMATED`或`DERIVED`；
- `CONFIDENCE`为`LOW`、`MEDIUM`或`HIGH`；
- 无前一修订时，`previousPlanId`为空字符串且`previousRevision`为0。

头记录后允许以下记录，顺序不限：

```text
ALLOCATION "allocationId" "networkName" NETWORK_TYPE "profileId" \
  frequencyHz "channelId" "subnetId" "routePolicyId" enabled

MEMBER "allocationId" "platformId"
SLOT "allocationId" "slotId"

DEMAND "demandId" "businessType" "sourcePlatform" \
  "destinationPlatform" payloadBits requiredBandwidthBps \
  maximumDelayMs minimumPdrPercent

DEMAND_NETWORK "demandId" NETWORK_TYPE

CHANGE "changeId" CHANGE_TYPE "allocationId" "platformId"
```

`NETWORK_TYPE`为`LINK11`、`LINK16`、`SATCOM`或`CDL`，不接受`UNKNOWN`。
`CHANGE_TYPE`为`JOIN`或`LEAVE`。`MEMBER`、`SLOT`和`DEMAND_NETWORK`通过显式ID
引用所属记录；文件解析完成后仍无法解析的引用会拒绝整个文件。

## 4. 严格解析规则

- `planId + revision`、`allocationId`、`demandId`和`changeId`不得重复；
- 必需ID、配置版本、provider和created time不得为空；
- revision必须大于0；
- payload、带宽、时延、频率不得为负，PDR必须位于0至100；
- 加载失败不得覆盖Repository中最后一个有效规划；
- 相同`planId + revision`不得静默覆盖当前活动规划或已生成文件；显式卸载后
  可重新加载同一规划文件；
- 加载后保存再加载必须保持值对象语义等价；
- 保存先在目标目录写临时文件并完成flush，再以原子rename发布；
- 目标文件已存在、写入失败或rename失败时保留原文件和当前Repository状态。

解析成功只证明内部语法成立。profile、频率、成员、业务类型、容量、资源冲突和动态入退网
规则由`NetworkPlanValidator`结合当前快照与版本化profile继续校验。
甲方专用校验规则未提供时，结果始终携带`CUSTOMER_RULE_UNAVAILABLE` WARNING；该警告
不阻止内部PRE_ACCEPTANCE流程，但禁止把内部校验解释为甲方最终校验。

## 5. 状态机

```text
DRAFT -- validation fail ----------------------------> REJECTED
DRAFT -- validation pass, evaluation fail -----------> REJECTED
DRAFT -- validation and evaluation pass -------------> VALIDATED
VALIDATED -- immutable local package generated ------> READY_FOR_DISTRIBUTION
任何表格编辑 ----------------------------------------> 新revision的DRAFT
```

校验和推演不修改输入规划、快照或AFSIM状态。状态转换记录在评估或分发结果中；本地分发包
包含状态为`READY_FOR_DISTRIBUTION`的不可变规划副本，不能向网络下发命令。

## 6. 本地分发包

仅当结构校验通过且所有业务需求推演均为`PASS`时，允许在显式输出根目录下生成：

```text
distribution_packages/<planId>/<revision>/
  network_plan.nrm
  validation_result.json
  evaluation_result.json
  manifest.json
```

manifest采用`nrm.network_plan_distribution.v1`，记录schema、planId、revision、
planFingerprint、configVersion、三个正文/结果文件名、生成时间和
`readyForDistribution=true`。校验、推演与分发包必须具有同一规划内容指纹，避免同一
planId/revision下复用陈旧结果。已存在的
revision目录不得覆盖。本阶段不调用网络接口、消息总线、OA接口或AFSIM控制API。
