# 甲方 JSON 接入与状态生命周期收口设计

## 目标

在不修改 AFSIM 核心、不破坏现有公开数据结构、不引入新第三方依赖的前提下，修复甲方 JSON 接入层中会影响合同演示和验收的状态混合、覆盖、乱序与语义漂移问题。

## 边界

- 保留现有 V1 JSON Schema 和插件入口。
- 运行时对已支持的 V1 消息执行严格的必填字段、字段类型、枚举、范围、未知字段和引用关系校验。
- 不实现通用 Draft 2020-12 JSON Schema 引擎。当前工程没有该依赖，Qt 5.12 也不提供相应能力；自行实现通用引擎会显著扩大范围。Schema 仍是对外接口规范，运行时代码覆盖本项目实际使用的全部 V1 字段。
- 资源规划继续定义为“规划合法性校验 + 当前/候选能力约束下的只读推演”。规划文件没有定义完整物理拓扑边时，不生成虚假的规划后网络。

## 设计

### 1. 具体网络身份

`EndpointSnapshot::networkName` 和 `LinkSnapshot::networkName` 继续保留现有名称以避免接口破坏，但其语义固定为具体 `networkId`。网络汇总、成员归属、链路归属均按该字段匹配，`networkType` 只用于四类网络分类和可视化。

同一类型可以有多个独立网络，例如两个 Link-16 网络。任何汇总都不得仅按 `networkType` 合并。

### 2. 消息生命周期

新增纯 C++ `CustomerIngestionState`：

- 按 `(runId, messageId)` 去重；
- 按消息域记录最后 `simTime`，拒绝同一运行内的陈旧状态；
- 新 `runId` 清空域时间并退休旧运行；
- 迟到的退休运行消息拒绝回灌；
- 使用有界集合保存消息标识，避免长期运行无限增长。

规划、评估等没有仿真时间的命令消息只做消息标识去重，不参与状态时间排序。

### 3. 快照合并

新增纯 C++ `CustomerSnapshotAssembler`：

- `resource_report` 更新网络、端点和链路，但保留同一运行已接收的导航与环境状态；
- `navigation_report` 按平台名称 upsert，不覆盖其他平台；
- `environment_report` 只更新环境域；
- 每次接受状态更新都产生单调递增的内部 `snapshotVersion`，全局 `simTime` 不回退；
- 新运行从空快照开始，避免跨运行污染。

### 4. 环境上下文

环境快照补齐并持久化以下 V1 字段：

- 地形阻断链路标识；
- 云量；
- 太阳高度角；
- 干扰影响链路标识；
- 干扰容量缩放系数；
- `applicationMode` 对应的参数化影响开关。

环境评估器只对明确受影响的链路应用参数化影响；缺字段时保留当前简化模型的安全默认值。

### 5. 规划配置版本

JSON 解码器不再写死 `customer-json-v1`。规划进入 `DataContainer` 后绑定当前启用的网络配置版本，再交给统一接纳函数完成校验、存储、推演和建议生成。

### 6. 评估请求闭环

`assessment_request` 进入 `DataContainer` 后使用当前版本快照和当前配置仓库执行 `AssessmentEvaluator`，缓存结果并生成标准响应。界面手工评估也复用同一入口，避免两套逻辑漂移。

### 7. 缓存一致性

快照版本变化后，所有依赖旧快照的评估、通信能力、规划推演、需求匹配和分发结果均失效；界面不得继续把旧结果显示为当前结果。

### 8. Provider 会话

`provider_hello` 至少记录最新提供者身份和能力声明，不再仅解码后丢弃。它用于诊断接口是否完成握手，不自动授予控制权限。

## 测试策略

- 先写失败测试，再实现最小修复。
- 纯状态逻辑放在无 Qt、无 AFSIM 依赖的头文件中单元测试。
- Codec 测试覆盖同类型多网络、环境完整字段、非法引用、未知字段和配置版本。
- 最终执行全部 C++ 测试、Shell 回归、Schema 校验、部署契约检查和 25 节点场景。
