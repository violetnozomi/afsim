# 合同遗漏功能最小化补齐设计

_状态：设计基线待用户复核 · 日期：2026-08-14_

## 1. 目标

在不修改 AFSIM 核心、不实现真实军标协议、不引入外部服务框架的前提下，把合同转录基线
3.2.1 至 4.2 中尚未闭环的显性功能补齐为可编译、可演示、可上报、可测试的参数化实现。

完成后必须同时满足：合同字段可见、输入能够加载、算法确实消费输入、输出包含固定原因码，
以及文档、JSON Schema、Codec、Warlock 页面和自动测试保持一致。所有参数化结果继续标记
`PARAMETERIZED_MODEL/LOW`，不得冒充真实协议或装备测量。

## 2. 方案选择

### 方案 A：在现有公共值对象和服务上增量补齐（采用）

保留 `ResourceSnapshot`、能力服务、规划服务、需求匹配、Warlock 和 Reporter，只增加小型
值对象与纯 C++ 计算器。优点是改动可分批提交、已有测试可复用、失败可按提交回退；缺点是
部分合同功能采用参数化近似，不等同于真实协议。

### 方案 B：另建独立合同演示程序（不采用）

开发速度快，但会与 AFSIM 实际状态和现有插件形成两套数据，不能证明合同能力属于 AFSIM
插件，后续联调也需要重写。

### 方案 C：直接实现完整协议和网络服务（不采用）

理论完整度高，但一个月范围不可控，而且甲方协议参数、封装规范和安全规范均未提供。

## 3. 全局约束

1. 不修改 AFSIM 核心源码；所有变化位于 `network_resource_manager`。
2. 不增加第三方依赖；公共核心保持纯 C++，JSON 边界继续使用 AFSIM 自带 Qt。
3. 只输出状态、计算结果和建议，不自动改变运行网络、频率、路由或平台状态。
4. 每个里程碑采用测试先行，独立提交；任何里程碑失败均可回退到上一提交。
5. 甲方数据优先于 AFSIM 观测，观测优先于推导，推导优先于参数化，参数化优先于估算。
6. 缺失数据使用 `valid=false` 和固定原因码，不以零值伪装测量。
7. 默认规模为 25 个平台；算法必须保持有界，不新增后台无限队列。

## 4. 里程碑一：合同状态对象与接口一致性

### 4.1 新增公共状态

在纯 C++ 公共类型中增加以下最小对象：

- `GeoPoint` 和 `OperationalArea`：区域 ID、多边形顶点、开始/结束仿真时间；多边形至少三个
  点，时间结束值不得小于开始值。
- `PlatformAttitude`：平台 ID、航向、俯仰、横滚和采样时间。
- `ResourceAlarm`：告警 ID、严重度、对象 ID、固定原因码、开始时间、是否活动。
- `ProtocolResourceState`：协议资源类型、容量、已用、剩余和占用率；用于轮询单元、时隙、
  卫通波束信道和 CDL 信道。
- `CoverageState`：最大传输距离和圆形近似覆盖范围；不实现 GIS 面覆盖计算。
- `ResourceProxyState`：提供方 ID、资源类型、更新时间、有效性和置信度，作为图 3-1/3-4
  中“资源代理”的最小软件对象。
- 链路增加 `supportedBusinessTypes`、`communicationQualityPercent`、`subnetId`、
  `protocolResource` 和活动告警引用。

### 4.2 精简外部 JSON

`resource-report.v1` 扩展为与公共对象一致的全量快照，保留现有最小字段兼容，并新增可选的
区域、姿态、覆盖、协议资源、路由、业务流、网关、资源代理和告警数组。新增
`provider-hello.v1` 与 `ingest-ack.v1` Schema；现有文件入口负责 Schema 校验和原子发布，
不实现 TCP。

文档只描述实际存在的 Schema 和字段。统一机器 Schema 使用独立文件集合，不再引用不存在
的聚合文件。

### 4.3 指标补齐

`ContractMetricEnricher` 只补充能够由已有状态可靠推导的字段：

- 质量分数使用有效的 PDR、SNR、BER 和时延分项等权重归一化；无有效分项则无效。
- 覆盖距离使用网络剖面最大距离，标记参数化低置信度。
- 协议资源占用率使用 `used / capacity`；容量为零时无效。
- 告警由链路离线、队列超过 80%、资源占用超过 90%、干扰观测和数据过期产生固定原因码。

## 5. 里程碑二：简化协议、频点和环境计算

### 5.1 频点特性

新增 `FrequencyCharacteristic`，按网络类型和频率保存：最大距离、容量比例、附加时延、
候选 PDR、干扰门限和保护带宽。内置演示配置每类网络至少提供两个频点，外部配置采用严格
版本格式，非法配置整体拒绝并保留上一有效版本。

候选链路计算依次应用网络基础剖面、频点特性和环境效果。实际已建立链路继续使用 AFSIM
观测，不重复扣减。

### 5.2 参数化协议行为

不实现报文位级协议，只实现资源管理需要的行为：

- Link-11：轮询单元容量、轮询周期和应答超时；资源耗尽或预测应答超时则不可满足。
- Link-16：时隙总量、单任务时隙需求和帧等待时延。
- 卫通：波束数、每波束信道数和单跳传播附加时延。
- CDL：并发链路数、信道数和高速率容量。

协议状态由配置和并发评估共同产生，进入快照、规划推演、需求匹配、Warlock 和 JSONL。

### 5.3 环境输入

能力请求消费区域、任务时间和平台姿态：

- 区域多边形只做端点是否位于边界内的二维检查。
- 地形使用 AFSIM 已有遮蔽结果和端点高程；没有地形库时保持无效。
- 气象记录有效时间段，只有覆盖任务时间才应用参数化效果。
- 姿态用简化天线指向容差判断；未配置定向天线时不影响链路。
- 干扰按中心频率、带宽和保护带判断重叠，重叠时应用容量/PDR/时延修正。
- 天象只提供时间与几何证据，没有明确参数时不改变通信能力。

## 6. 里程碑三：规划协同与资源管理闭环

### 6.1 规划协同

规划增加 `planningDomain`，允许 `AIRBORNE`、`GROUND` 和 `JOINT`。动态入退网请求经现有
Codec 转换为 `NetworkPlanChange`，应用时始终生成新修订：加入已存在成员、退出不存在成员、
规划 ID 不匹配或引用不存在均拒绝，旧规划保持不变。

本地分发采用“发件箱/收件箱”验收替身：生成不可变分发包后写入 `outbox`，读取方把同一
内容指纹和修订写入 ACK 文件后状态变为“已确认”。该流程只模拟机上/地面协同证据，不调用
真实网络协议或 AFSIM 控制接口。

### 6.2 需求监听与反馈

新增纯 C++ `ResourceDemandCoordinator`：

1. 接收带 `requestSource`、`correlationId` 和任务阶段的需求集；
2. 按连通性、性能、规模和流量生成固定分类标签；
3. 使用当前规划、资源快照和既有并发评估完成匹配；
4. 返回同一 `requestSource/correlationId` 的结构化结果；
5. 记录最近同业务类型的有限历史摘要，用于输出“历史同类任务通过率”，不建立数据库。

历史只保留最近 128 批摘要，进程结束时写 JSONL；它只提供规划参考，不自动改变评分门限。

### 6.3 干扰规避与六类建议

频率建议必须先排除占用候选，再排除与活动干扰频带及保护带重叠的候选，最后按预测最小
裕量降序、频率升序选择。站点、信道、子网、时隙和路由继续使用有限候选和现有能力结果。
每类建议都必须输出 `AVAILABLE` 或稳定的不可用原因。

## 7. 里程碑四：导航、恢复、兼容和验收证据

### 7.1 导航精度

保留 AFSIM `.neh` 和实时导航误差作为直接输入。新增简单 `NavigationAccuracyProfile`，按
`GNSS/INS/INTEGRATED`配置水平、垂直和航向 1σ 精度；当外部数据没有误差时，根据配置形成
参数化精度结果。已有直接误差永远优先，不实现卫星定位或惯导积分算法。

### 7.2 运行恢复

增加恢复清单，启动时检查最后一次运行 manifest、规划/需求修订和未确认分发包。异常终止
后新进程使用新 runId，恢复最后一个校验通过的配置和只读规划副本，不恢复仿真时间或未完成
通信任务。测试使用强制终止辅助进程模拟异常断电，不进行真实设备断电。

### 7.3 第三方兼容样例

增加一个最小 `ReferenceModelAdapter` 测试模块，使用现有 `ModelRegistry` 注册、查询、调用
健康检查和卸载。它证明公共封装边界可被第三方实现，不扫描动态库，也不声称符合尚未提供的
甲方正式封装规范。

### 7.4 部署证据

新增只读部署检查脚本，输出 CPU 架构/核心数/频率、内存、磁盘和网卡能力，以及 Linux、
AFSIM、编译器和插件版本。OA、保密、TLS和甲方门户没有规范时标记 `CUSTOMER_BLOCKED`，
不得标记通过。小型局域网只检查配置的监听地址和连接能力，不开放默认公网端口。

## 8. Warlock 与上报

保持现有响应式中文界面，不新增顶层窗口：

- “环境状态”增加区域、有效时间和姿态摘要；
- “通信链路”增加覆盖、质量、业务类型、子网、协议资源和活动告警；
- “资源规划”增加规划域、动态入退网结果和本地分发 ACK；
- “需求匹配”增加请求来源、分类、反馈状态和历史同类通过率；
- “预验收状态”增加全文合同检查，不只显示表 3-1 的 30 行。

Reporter 增加版本化 JSONL：`resource_alarms.jsonl`、`demand_feedback.jsonl`、
`planning_coordination.jsonl` 和 `deployment_checks.jsonl`。队列保持有界并沿用 runId 隔离。

## 9. 测试与验收

每个新行为必须先增加失败测试，再写最小实现。固定验收包括：

1. Schema 正例、缺字段、引用错误、未知字段和旧版最小资源包兼容。
2. 多边形内外、气象时段覆盖、姿态容差、干扰频带重叠和频点排序。
3. 四类协议资源正常、达到上限和超出上限。
4. 动态 JOIN/LEAVE 新修订、旧规划不变、分发 ACK 指纹一致和不一致。
5. 需求来源回显、分类、并发冲突、六类建议和 128 批历史上限。
6. 导航直接误差优先、三类参数化精度和非法配置回退。
7. 异常终止恢复、损坏状态拒绝、第三方参考适配器注册/卸载。
8. 25 平台综合场景显示四网、主备路由、协议资源、告警和建议。
9. `ai_guard.sh static`、`contract`、`test`、批准场景和一键预验收全部通过。

## 10. 完成口径

仅当某项具有公共字段、真实调用链、Warlock/JSON输出和自动测试时才标记
`IMPLEMENTED / PRE_ACCEPTANCE`。依赖甲方正式封装规范、OA/保密规范、目标 AFSIM 树、
真实协议参数或第三方参考模块的项目统一标记 `CUSTOMER_BLOCKED`，不得用内部样例提升为
`FINAL_ACCEPTANCE`。
