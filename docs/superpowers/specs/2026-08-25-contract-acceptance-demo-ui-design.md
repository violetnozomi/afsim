# 合同验收演示前端设计

## 1. 目标

在不修改 AFSIM 核心、不改变现有评估算法和只读控制边界的前提下，为 Warlock 网络资源
管理器增加一个面向非技术验收人员的“合同验收演示”页面。演示人员应能从一个页面启动固定
综合场景，按合同功能顺序进入已有页面，并使用已经冻结的示例参数完成录像。

该页面是现有能力的展示编排层，不重新实现资源采集、任务评估、通信能力、规划、需求匹配、
导航或环境计算。

## 2. 使用场景

演示人员通过 VNC 打开 Warlock 后进入“合同验收演示”页，执行以下固定流程：

1. 启动综合验收场景并加载复杂资源规划；
2. 查看四网资源、成员、链路和窗口指标；
3. 使用固定示例执行任务评估并查看算法逐跳主备路由；
4. 使用固定示例查询通信能力和数值差距；
5. 校验并只读推演资源规划，查看失败原因和中文调整建议；
6. 查看跨域网关、导航和环境证据；
7. 查看最近一次内部预验收摘要。

命令行预验收仍作为开发证据保留，但不作为甲方录像的主要操作界面。

## 3. 方案选择

采用“单一综合场景 + 前端步骤导航”方案。综合场景复用：

- `test_mission/operational_strike_demo/interactive.txt`；
- `data/network_plans/operational_25node_complex-r1.nrm`；
- `scripts/remote/switch-warlock-plan.sh`。

不增加多场景任意文件选择器，不在插件中实现 shell 控制台，也不把所有自动测试暴露为 GUI
按钮。这样可以只重启 Warlock 一次，并避免录像过程中频繁切换场景。

## 4. 前端结构

新增 `NrmAcceptanceDemoPanel`，作为独立 Qt Widget 放入主标签页。该组件只负责：

- 显示合同演示标题、当前步骤和简短拍摄提示；
- 显示固定步骤卡片及其对应合同条款；
- 发出“启动综合场景”“打开目标页”“填充示例并执行”意图信号；
- 显示由 `DockWidget` 提供的当前快照和预验收摘要；
- 使用“通过／降级／待执行／失败”中文状态，不要求甲方理解内部枚举。

`NrmDockWidget` 继续持有已有业务控件和调用入口，并负责把面板意图映射到现有方法：

- 切换 `QTabWidget` 当前页；
- 填充已有源、目的、网络和 QoS 控件；
- 调用已有 `EvaluateTask()`、`QueryCapability()`、`ValidateNetworkPlan()` 和
  `EvaluateNetworkPlan()`；
- 复用现有规划场景切换逻辑启动固定综合场景。

演示面板不直接访问 AFSIM 对象，不持有仿真对象指针，也不复制业务算法。

## 5. 固定演示数据

任务评估示例固定为：

- 源平台：`airborne_relay`；
- 目的平台：`gw_l11_l16_reverse`；
- 允许网络：`LINK16`；
- 带宽：`0 kbit/s`，表示不启用带宽硬门限；
- 最大时延：`1000 ms`；
- 最低 PDR：`0%`，避免无观测 PDR 把路由展示阻断。

预期当前主路由为：

```text
airborne_relay
→ network_control_center
→ gw_l11_l16_reverse
```

通信能力示例复用相同平台和网络，并保留页面现有默认 QoS。固定值只用于内部演示，不进入
甲方接口 Schema，也不覆盖用户手工输入。

## 6. 场景启动与安全边界

“启动综合验收场景”只允许调用仓库内固定场景和固定规划。实现复用现有
`QProcess::startDetached`、`systemd-run --user` 和 `switch-warlock-plan.sh` 路径，不接受用户
输入的程序、参数、场景或规划路径。

必须保持：

- 不提供任意命令输入；
- 不修改 systemd 服务文件；
- 不在仿真回调执行进程启动或文件 I/O；
- 不自动建链、改频、分配时隙或修改路由；
- 场景切换失败时保留当前 Warlock 和当前规划，并显示中文错误；
- 当前环境不支持用户服务时，显示“演示场景启动失败”，不伪装成功。

## 7. 状态与错误展示

页面状态只用于演示导航，不替代合同测试报告：

- `待执行`：尚未进入对应步骤；
- `可展示`：当前快照具备该页所需的基础数据；
- `降级展示`：使用参数化或估算数据，或存在甲方阻塞项；
- `失败`：场景启动或已有服务调用发生明确错误；
- `通过`：已有可复核结果满足该步骤的冻结演示条件。

资源规划返回 `REJECTED` 不直接等价于软件失败。只要失败需求同时提供原因码、数值差距和
中文调整建议，就属于“规划约束识别通过”。

## 8. 测试策略

生产代码前先新增失败测试，验证：

1. 面板包含全部中文步骤和合同条款；
2. 步骤按钮发出确定的动作，不执行任意命令；
3. 固定评估示例的源、目的和网络准确；
4. 综合场景启动只使用仓库固定场景与规划；
5. 场景启动失败能够显示中文失败状态；
6. 现有预验收状态页继续保持只读；
7. 小屏布局允许滚动，不增加固定最小宽高；
8. 现有 40 项固定测试不删除或放宽。

新增测试后固定测试数为 41。完成实现后运行静态检查、41 项固定测试、Warlock 插件构建，
并在 VNC 中人工核对综合场景启动、页面跳转、固定评估、规划建议、导航和环境显示。

- 甲方 JSON Schema；
- 跨域网关策略和自动网络控制边界。

## 10. 完成标准

- VNC 中可从“合同验收演示”页启动综合场景并自动恢复复杂规划；
- 非技术人员可按页面步骤完成一条连续录像，不需要终端命令；
- 固定任务评估显示当前两跳主路由和候选备路语义；
- 规划失败时可直接看到中文原因和调整建议；
- 导航、环境、跨域网关和预验收摘要均可从演示页一键进入；
- 41 项固定测试、静态检查和 Warlock 构建通过；
- AFSIM 核心修改数保持为 0。
