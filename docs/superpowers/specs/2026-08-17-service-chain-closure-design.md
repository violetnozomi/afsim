# 统一服务主链与甲方资源需求接口收口设计

## 结论

本轮评审方向合理，但部分结论已被上一轮实现覆盖。`assessment_request` 已能由
`DataContainer` 接收，导航支持多平台聚合，环境上下文能够保存，文件入口也能生成
ACK/错误/评估响应。仍需收口的有效缺口是：任务评估尚未经过
`ModelServiceFacade`；资源需求只有内部模型，没有甲方 JSON 请求/响应；当前实际工作的
V1 JSON 边界与抽象的未来传输 SPI 命名关系不够清楚。

## 本轮实现范围

1. 为 `ModelServiceFacade` 增加只读任务评估操作、端口、默认实现、响应类型、健康检查
   和能力描述；`DataContainer` 与界面继续共用唯一入口。
2. 定义精简的 `nrm.customer.resource_demand_request.v1` 和
   `nrm.customer.resource_demand_response.v1`，由甲方 AFSIM 模块按本方格式提供需求，
   插件完成解析、版本绑定、存储、并发匹配和结果编码。
3. 将现有 `CustomerJsonCodec` 明确命名为 V1 的具体合同适配器，同时保留原名称别名，
   避免破坏既有源码接口。

## 明确不在本轮伪造的能力

- `ContractInterfaceAdapter` 保留为未知甲方传输协议的 SPI；当前 V1 文件/进程内 JSON
  适配器不强行继承一组尚无具体请求载体的抽象接口。
- 规划文件没有声明潜在链路、节点运动或建链动作，不能据此构造可信的“规划后虚拟
  拓扑”；规划评估继续基于同一 AFSIM 快照检查资源分配和需求约束。
- 推荐结果只读，不自动改写规划。自动生成候选规划会扩大合同动作边界，并可能把建议
  冒充可执行配置。
- HTTP/TCP/MQ 等返回通道由甲方部署协议决定。本轮保持文件/进程内字节响应接口，传输
  适配器后续只需转发已编码字节，不进入模型核心。

## 资源需求最小字段

请求仅包含需求集标识、修订号和需求数组。单项需求包含源/目的平台、业务类型、带宽、
时延、PDR 和允许网络；任务阶段、业务流量、最大距离、最小网络规模为可选字段。插件
使用当前配置版本，不允许甲方 JSON 覆盖内部模型版本。

响应包含需求集、快照版本、总体计数以及每项需求的状态、原因码、所选网络/路由和中文
建议。所有结果均为只读建议，不触发建链、改频或路由变更。

## 状态与错误语义

资源需求请求复用现有消息生命周期：重复消息返回幂等 ACK/缓存响应，旧消息拒绝，新
`runId` 清理上一运行的外部状态。解析成功但业务校验不通过时仍返回结构化需求响应；
JSON 或生命周期错误返回统一错误响应。
