### 前端合同验收录像流程

Warlock右侧默认打开`合同验收演示`页。该页不要求输入平台ID、文件路径或终端命令，按页面
九个步骤从上到下拍摄即可：

1. 点击`启动固定综合场景`。插件只使用仓库内固定的综合场景与复杂规划；Warlock窗口会短暂
   消失，数秒后重新出现并返回`合同验收演示`页；固定规划已在后台自动加载。摘要应显示
   4类网络、综合场景平台/链路/跨域网关数量、导航平台数以及地形、气象、电磁环境有效性。
2. 点击`查看四网资源总览`，拍摄Link-11、Link-16、卫通、CDL四网统计；中央态势图始终保留，
   可同时拍摄平台、链路和作战通信拓扑。
3. 回到演示页点击`执行固定任务评估`。系统自动选择
   `airborne_relay → gw_l11_l16_reverse`、`LINK16`、0千比特/秒、1000毫秒、0% PDR，
   预期主路由经`network_control_center`形成两跳当前路径。
4. 点击`查询固定通信能力`，查看同一源/目的条件下的距离、速率、丢包率、时延、吞吐量、
   接入率及数据质量。
5. 点击`查看资源规划推演`。按钮会自动执行规划校验和只读推演，并直接切到`推演结果`或
   `调整建议`。规划状态为`REJECTED`不等于软件失败；能够显示冲突原因、数值差距和中文建议，
   就证明约束识别与规划建议链路正常。
6. 点击`查看跨域网关链路`，拍摄12个跨域网关相关链路及中央态势中的网关节点。
7. 点击`查看导航状态`，拍摄导航真值、感知值和误差。
8. 点击`查看环境状态`，拍摄地形、气象和电磁干扰证据。
9. 点击`查看预验收证据`，拍摄最近一次固定测试和场景计数。该页只读，不从GUI运行批量测试。

所有评估、能力和规划动作都只输出结果或建议，不会自动建链、改频、分配时隙或修改路由。

### 第三步：查看四网数据

Warlock默认打开：

```text
test_mission/four_network_overview.txt
```

窗口中央显示 AFSIM 实际平台状态和通信拓扑。三角形是飞机，方形是地面节点，
菱形是卫星/卫通节点；四类网络按蓝色 Link-11、红色 Link-16、紫色卫通和绿色
CDL 区分。标题下方的快照版本和仿真时间持续变化，说明画面来自 AFSIM 实时状态。
链路上移动的同色光点表示近10秒内确实发生过AFSIM消息收发或转发，移动方向就是消息的
源端到目的端；没有近期消息的链路只显示静态底线，系统不会为了动画伪造通信事件。

当前界面采用现代深色态势风格：右侧顶部用指标卡片显示运行、上报、仿真时间、网络/端点、
收发、转发和失败统计；页签、表格、输入框和按钮使用统一视觉状态。中央图按物理平台去重，
同一平台接入多种网络时在节点下方显示多个彩色徽点；链路只用颜色和线型编码，不再为每条
链路重复绘制网络名称。密集场景中的标签会自动尝试六个位置避碰，空间不足时保留节点图形，
完整名称仍可在`网络成员`页查看。

进入`任务评估`页，从下拉框选择源节点和目的节点后点击评估。中央区使用黄色粗线
显示主路由、青色线显示备选路由；实线是当前链路，虚线表示需要先建立的参数化候选
链路。源节点和目的节点分别带绿色和橙色圆环。候选结果只给出建议，不会自动改变仿真。

右侧`网络资源管理器`面板默认可见，包含：

1. `四网总览`：四类网络累计汇总
2. `窗口指标`：默认四网10秒运行摘要；二级“1/10/60秒技术明细”保留全部窗口值
3. `网络成员`：平台、通信设备、地址、状态和位置
4. `通信链路`：默认显示最近10秒实际有业务的链路；二级“全部链路与技术字段”保留完整有向图
5. `任务评估`：输入任务约束并显示当前图、候选图和主备路由评估结果
6. `通信能力`：查询六项能力指标、路径和数据质量

小屏或Windows远程VNC下，顶部运行概况默认收起。需要查看累计状态时点击标题区右侧的
“展开运行概况”；再次点击即可收起，把垂直空间让给当前功能页面。Dock初始建议尺寸为
720×620，表格同时支持水平和垂直滚动。

界面中的状态、来源、置信度、降级等级、校验原因及合同指标字段均采用中文说明，并在括号
中保留稳定英文编码，便于与JSON、日志和甲方AFSIM模块联调。该翻译只发生在Warlock显示
层，不会改变规划文件、JSON Schema、CSV或上报接口中的英文枚举。

所有资源表格均支持拖动表头分隔线调整列宽。成员、依据、原因等长文本不会再自动撑大整个
窗口：单元格超出列宽时显示省略效果，鼠标悬停可查看全文，也可使用底部水平滚动条。综合
态势画布和各表格不再设置固定最小宽高，可通过Warlock停靠面板边界继续缩小或放大。

加载带内嵌`# NRM_SCENARIO`场景绑定的演示规划时，如果当前仿真节点不匹配，Warlock会自动关闭并
在数秒后以绑定场景重新出现；规划随后自动恢复，页面自动进入“资源规划”。VNC连接不会
断开。旧版`.scenario`侧车文件仍可兼容。普通甲方规划没有场景绑定，因此只使用甲方当前AFSIM场景。

从`合同验收演示`点击`启动固定综合场景`是上述规则的唯一页面例外：规划仍会自动恢复，
但新窗口返回`合同验收演示`，直到第5步点击`查看资源规划推演`才进入“资源规划”。

复杂37节点样例绑定的是长期交互版场景。该入口显式启用实时模式并把初始时钟倍率固定为
1×，避免继承Warlock上一次保存的高倍速；0–180秒按墙钟速度展示完整业务和链路事件，180秒后
自动降至0.0001×驻留，并通过周期时钟保护防止Warlock控制器重新套用高倍速。这样可持续查看
最终拓扑、指标和规划结果，同时限制长期调试的快照增长。交互入口在180秒前额外周期发送
Link-11、Link-16、SATCOM和CDL真实消息，因此驻留后的近10秒活动光点仍可用于录像；
命令行自动验收仍使用固定180秒版本，不包含这组交互专用消息。

自动切换由独立的systemd临时单元完成：界面先提交一次性的“场景路径+规划路径+可选返回页”请求，
临时单元再对正式服务执行一次原子重启；`nrm-warlock.service`读取请求并启动绑定场景，同时通过
`NRM_AUTO_PLAN_FILE`恢复规划；验收启动额外使用一次性的`NRM_AUTO_OPEN_PAGE=acceptance`
返回步骤页。新进程仍由正式服务管理，不会成为脱离systemd的孤立进程。
可使用下面的命令核对实际启动场景：

```bash
WARLOCK_PID=$(systemctl --user show -p MainPID --value nrm-warlock.service)
tr '\0' ' ' <"/proc/${WARLOCK_PID}/cmdline"
```

8. `需求匹配`：加载需求集、编辑新修订、批量匹配并查看差距和六类建议

面板较窄时，后面的页签会隐藏在页签栏右侧箭头中；点击右箭头或拖宽Dock面板即可看到

### 一键内部预验收

Linux服务器执行：

```bash
cd /home/pyh/afsim/network_resource_manager
./scripts/run_preacceptance.sh
```

Windows PowerShell远程执行：

```powershell
ssh -F NUL pyh@10.129.10.207 'cd /home/pyh/afsim/network_resource_manager && ./scripts/run_preacceptance.sh'
```

该命令自动完成31项测试、九个批准场景和一次Warlock 120秒最终快照核对。所有检查通过时
输出`Overall: PASS`；失败时返回非零退出码。详细报告位于
`output/preacceptance/<UTC时间戳>-<进程号>/PREACCEPTANCE_REPORT.md`，原始输出在其
`logs/`目录。运行期间不需要操作Warlock界面。

脚本同时原子更新`output/preacceptance/latest_status.json`。Warlock的`预验收状态`页约
每2秒自动读取并显示该文件；运行中为`RUNNING`，结束后为`PASS`或`FAIL`。脚本会重启
Warlock一次，因此VNC窗口短暂消失是正常现象，重新出现后无需手工刷新页面。

### 甲方JSON接口契约校验

接口字段、时序、错误码、同进程接入方式和待甲方确认项见
`docs/甲方接口对齐规范与JSON-Schema.md`。本地验证统一Schema和13类示例：

```bash
./scripts/ai_guard.sh contract
```

当前接口状态为`BASELINE_DRAFT`。命令通过只证明Schema与项目示例一致，不代表甲方已经
签字，也不代表甲方私有对象转换、ABI兼容和目标环境联调已经完成。正式运行时采用同进程
`CustomerNrmAdapter`，不要求TCP Adapter。

通过“加载甲方JSON”载入资源、导航或环境报告时，插件按`runId/messageId/simTime`自动
去重和拒绝迟到数据；资源报告不会清空已有导航/环境，导航报告会按平台追加或更新。载入
任务评估请求后会立即使用当前快照执行评估，结果显示在“任务评估”页并写入上报目录。

同一入口也可加载
`schemas/customer/v1/examples/resource-demand-request.example.json`。插件会将其中多个
通信任务作为一个需求集并发评估，结果写入“需求匹配”页；已编码的逐需求状态、原因码和
只读建议可由`LastCustomerJsonResponse()`交给后续甲方传输适配器。

## 🔍 数据解释

### 页面顶部状态

| 字段 | 含义 |
| --- | --- |
| `Version` | 当前加载的插件版本，应为`0.12.1` |
| `Runtime state` | `Initializing`、`Running`、`Complete`或`Idle` |
| `Simulation time` | 当前快照对应的仿真时间，不是墙钟时间 |
| `Networks/Endpoints` | 当前快照中的网络数和通信端点数 |
| `Transmitted/Received` | 本次仿真从启动到当前的累计消息数 |
| `Message hops` | AFSIM实际产生的逐跳回调累计数 |
| `Discarded/route failed` | 丢弃数和路由失败数，二者分别统计 |

### 四网总览页面

该页面用于快速确认四种网络是否正确接入。`Tx`、`Rx`和`Dropped`是累计值，不会随着
窗口滚动而下降。`成员数`是通信端点数，不等同于平台数；同一平台装有两套通信设备时会
计为两个端点。

| 列 | 数据来源 |
| --- | --- |
| `Type` | 显式网络命名分类 |
| `Network/Model` | AFSIM网络名称和脚本模型类型 |
| `成员数/在线数` | 当前端点总数和在线端点数 |
| `链路数` | `GLOBAL_TRUTH`图中当前启用的有向边数 |
| `Tx/Rx/Dropped` | 本次仿真的累计通信事件 |

### 窗口指标页面

默认打开“运行摘要”，每种网络只显示一行10秒数据，适合合同录像。速率自动使用
`bit/s`、`kbit/s`或`Mbit/s`，网络内部编号转换为中文用途名称。摘要中的“参考带宽”来自当前
四网参数模板，不冒充AFSIM实测带宽；“参考占用率”是10秒交付业务量除以该模板容量，均明确
标注“（参考）”。通信模型没有提供队列上限时显示“未建模”，不会用0或横线造成误解。

二级页签“1/10/60秒技术明细”仍按每个网络三行显示原始统计值。窗口基于仿真时间，仿真暂停
时不会继续滚动。验收人员看“运行摘要”，开发联调和指标追溯再进入技术明细。

固定37节点交互场景从仿真第10秒起持续发送四网质量探测业务。四网采用不同的发送周期和
报文长度抖动，并通过AFSIM通信设备的固定种子非周期短时中断形成五阶段动态PDR：10–40秒
健康，40–80秒轻度退化，80–120秒强干扰，120–150秒恢复，150–180秒稳定。一次基准运行的
强干扰阶段为`Link-11 74.12% / Link-16 86.02% / SATCOM 70.67% / CDL 91.47%`，恢复阶段
分别回升至`87.50% / 94.20% / 80.70% / 92.78%`。这不是界面填充的固定数字：每个数值仍由
发送、接收事件计算，10秒窗口会随非周期丢包和阶段切换上下波动。

| 列 | 计算口径 | 无效条件 |
| --- | --- | --- |
| `Throughput` | 同一发送队列中最终交付比特数/窗口秒数 | 窗口长度非法 |
| `PDR` | 同一发送队列中交付终态数/发送数 | 窗口无发送消息或发送分母不可靠 |
| `Online ratio` | 窗口内各快照在线端点比例的平均值 | 窗口无状态样本 |
| `Queue delay` | 同一消息发送时刻减排队时刻的平均值 | 无法关联消息 |
| `Transport delay` | 同一消息接收时刻减发送时刻的平均值 | 无法关联消息 |
| `队列占用率` | 队列深度/队列上限；未提供上限时使用默认128 | 队列上限为0 |
| `ACK` | 事务关联的ACK时延；无事务标识时暂用单向时延估算 | 无传输时延样本 |
| `RTT` | Ping/Pong关联；无事务标识时暂用单向时延的2倍估算 | 无传输时延样本 |

命令行可重复性检查：

```bash
bash tests/PdrDiversityScenarioTest.sh
```

输出的20行`NRM_PDR_PHASE_RESULT`必须显示“健康→退化→强干扰→恢复→稳定”的趋势，四网
样本量不能完全相同，多数非健康结果不能量化为5%的整数倍，且连续两次运行完全一致。上述
百分比属于内部参数化演示观测值，不代表甲方装备性能。

启动未满10秒或60秒时，窗口仍按完整窗口长度计算速率。v0.7 另行输出
`offeredLoadBps` 和 `deliveredThroughputBps`，并使用 messageId 关联发送与单一终态；组播
预期接收者展开和重传语义仍属于后续适配。

### 网络成员页面

状态优先级为`FAILED`、`DISABLED`、`OFFLINE`、`ONLINE`。经纬高来自平台当前位置。
地址是AFSIM通信地址，不是甲方装备编号。“职责”优先显示输入值；缺失时按平台名称和
网络类型推断，并作为`ESTIMATED/LOW`数据。合同逐项证据见
[合同30项指标实现矩阵](合同30项指标实现矩阵.md)。

### 通信链路页面

默认打开“活动链路（最近10秒）”，只列出最近10秒确实发生过排队、发送、接收、转发或交付
业务量的有向链路。平台编号转换为中文名称，距离自动使用米/千米，容量和占用率使用明确标注
的四网参数模板参考值；质量优先显示有效综合质量/SNR，否则使用当前窗口PDR作为依据。

二级页签“全部链路与技术字段”保留AFSIM全局图中的全部有向边，因此A到B和B到A分别显示。
`10 s throughput`是该方向成功到达接收端的交付吞吐量。只有最近一次接收结果提供有效
`bandwidth`时才计算原始`Utilization`。

| RF列 | 有效条件 |
| --- | --- |
| `Bandwidth` | `WsfCommResult.mDataRate > 0` |
| `RSSI` | 接收功率大于0瓦，换算为dBm |
| `SNR` | 绝对信噪比大于0，换算为dB |
| `BER` | 比特错误率不小于0 |

不满足有效条件时，技术明细显示`—`；运行摘要则显示“未建模”“接口未提供”或采用明确标注的
参数模板参考值。这些状态都不是数值为零，也不会伪造RSSI、SNR或BER。

### 任务评估页面

输入字段：

| 字段 | 说明 | 输入0的含义 |
| --- | --- | --- |
| `源平台` | 源平台名称，必须与网络成员页面完全一致 | 不适用 |
| `目的平台` | 目的平台名称 | 不适用 |
| `Allowed network` | `ALL`或限定一种网络 | `ALL`允许四网 |
| `Required bandwidth` | 任务最低带宽，单位kbit/s | 不检查带宽 |
| `Maximum delay` | 允许的端到端预测时延，单位ms | 不检查时延 |
| `Minimum PDR` | 最低路径成功率，单位% | 不检查可靠性 |

点击`Evaluate current / candidate graph`后显示：

| 输出 | 解释 |
| --- | --- |
| `Reachable` | 当前已启用、允许类型的有向图是否存在路径 |
| `Can establish now` | 0.4版本等于当前路径存在；尚不包含潜在建链 |
| `Can complete` | 路径存在且所有已输入硬约束通过 |
| `Stable` | `Can complete`为真且路径PDR不低于80% |
| `Primary route` | 最低预测时延主路径的平台序列 |
| `Predicted delay/PDR` | 路径逐跳时延求和、逐跳PDR乘积 |
| `Margin` | 当前能力减需求，正数有余量，负数不足 |
| `Reason codes` | 固定、可测试的失败原因 |
| `Recommendation` | 只读建议，不修改仿真 |

默认输入`l11_control → l11_member`、带宽0、时延1000ms、PDR 90%，可直接验证正常
路径。通用演示网络没有有效容量；若把最低带宽设为正数，结果应返回`DATA_INVALID`，这是
正确的数据质量保护。

网络分类来自场景中的显式命名约定：

| 命名标记 | 分类 |
| --- | --- |
| `link11`、`link_11`、`nrm_l11` | Link-11 |
| `link16`、`link_16`、`nrm_l16`、`jtids` | Link-16 |
| `satcom`、`satellite`、`nrm_sat` | 卫通 |
| `cdl` | CDL |

`J11.x`不会被识别为Link-11。没有匹配标记的网络保留为`UNKNOWN`；无成员的AFSIM默认
网络不会显示在资源面板。

### 通信能力页面

候选链路才读取`NRM_ENVIRONMENT_CONFIG`指定的严格配置，并标记

### 资源规划页面

甲方修改版 AFSIM 可直接提供项目定义的精简 JSON。进入“资源规划”页，点击“加载”，
选择 `schemas/customer/v1/examples/network-plan.example.json`；也可继续加载原有 `.nrm`
文件。插件先完整转换为公共 `NetworkPlanDocument`，成功后才替换当前规划；失败不会破坏
上一份有效规划。审计结果写入当前运行目录的 `customer_interface_events.jsonl`，不记录
原始载荷。

合同录像使用以下两个新文件，不再用旧的25节点规划代替：

- 资源规划：`data/network_plans/contract_acceptance_37node-r1.nrm`；内嵌场景绑定，加载后可自动切换37节点综合场景。
- 需求匹配：`data/resource_demands/contract_acceptance_37node-r1.demand`；在“需求匹配”页单独加载并执行匹配。

“需求匹配”页不再同时纵向堆叠多张小表，而是使用“业务需求、匹配结果、约束差距、调整
建议、技术依据”五个二级页签。加载后先核对业务需求；点击“执行匹配”后，全部满足时自动进入匹配
结果，存在失败且有建议时自动进入调整建议，没有建议时进入约束差距。每张表独占剩余内容区。
调整建议默认按任务聚合，验收人员只需查看“通信任务、结论、建议资源、建议路由、原因说明”；开发联调时再进入“技术依据”查看原始候选编号和证据。
后续实时快照使评估过期时，上一轮明细保留供查看，顶部会标明“已过期、仅供查看”及两个快照版本；
此时再次点击“执行匹配”即可用当前快照重算。

导航、环境和资源快照共用 `DataContainer::LoadCustomerJson` 接口。接入优先顺序固定为：
AFSIM 原生回调、同进程公共 C++ 对象、JSON 文件；导航历史回放仍使用 AFSIM `.neh` 格式。

规划中的 `demands` 数组同时也是并发评估的优先级顺序：排在前面的任务先预留其主路由
各跳带宽，后续任务使用剩余带宽重新评估。“并发结果”区分“可并发”“资源冲突”和
“独立评估未通过”，“冲突任务”显示占用了相同有向链路的先行任务编号。该过程只操作
快照副本，不会修改AFSIM中的真实链路。没有甲方专用字段时使用项目冻结的验收近似值：Link-11 每网 8 个
轮询单元、Link-16 每网 16 个时隙、卫通 4 波束且每波束 2 信道、CDL 4 条并发链路且
8 个信道。每个成功任务占用一个对应资源单元，并继续按任务需求扣减带宽。

页面操作状态会自动显示 `L0_TOPOLOGY`、`L1_LINK`、`L2_QUALITY` 或 `L3_RESOURCE`、
数据覆盖率、采用的默认值和缺失字段。最低 L0 数据仍可进行拓扑/候选链路判断；缺失的
质量字段只降低置信度，不导致插件加载失败。完全没有成员数据时才标记 `UNAVAILABLE`。

`资源规划`页默认进入“资源概览”，显示四网类型、资源用途、MHz/GHz频率、信道/波束、子网、成员数量、中文路由方式和启用状态。
原始`planId`、配置模板、Hz数值、成员ID清单和可编辑字段保留在“配置明细”；完整规划身份信息可通过顶部摘要的鼠标提示查看。`加载规划`和`卸载规划`只改变当前规划
仓库；卸载不会影响实时资源快照。

内置四网加载测试文件位于：

```text
/home/pyh/afsim/network_resource_manager/data/network_plans/four_network_demo-r1.nrm
```

先运行`test_mission/four_network_overview.txt`，再打开`资源规划`页并点击`加载规划`，
选择上述文件。成功后应显示规划ID`four-network-demo`、修订`1`、4条allocation和4条
demand。点击`校验规划`后应通过内部校验，并保留一条
`CUSTOMER_RULE_UNAVAILABLE`警告；该警告仅表示甲方专用规则尚未提供。点击`只读推演`
只评估当前资源，不会应用规划。若部分需求显示`DATA_INVALID`，应结合当前场景是否提供
完整带宽、时延和PDR测量判断，这不等同于文件加载失败。

表格编辑后，`保存新修订`创建递增修订并回到`DRAFT`，不会原地改写已校验
修订。`校验规划`执行结构、引用、剖面、成员和资源冲突检查；`只读推演`把每条
需求交给既有通信能力服务，只读输出`PASS / FAIL / DATA_INVALID`。未通过时页面自动切换
到独立“调整建议”二级页签，按需求显示状态、主要原因和完整中文建议，覆盖无路径、节点
离线、带宽不足、时延超限、PDR不足、数据缺失和并发资源冲突，无需横向滚动到推演表末端。
相同建议同时写入
`plan_evaluation_results.jsonl`的`demands[].recommendations`，便于验收留档。

这里的建议是“当前规划为何未通过以及怎么调整”的规划级建议。独立“需求匹配”页仍负责
频率、站点、信道、子网、时隙和路由六类结构化候选建议；两类结果都只读，不自动修改网络。

只有校验通过且全部需求为`PASS`时，`生成分发包`才会在显式选择的目录或
`NRM_PLAN_STORE_DIR`下生成：

- `distribution_packages/<planId>/<revision>/network_plan.nrm`；
- `validation_result.json`；
- `evaluation_result.json`；
- `manifest.json`。

规划正文使用内部`NRM_NETWORK_PLAN_V1`格式，完整语法见
[网链资源规划文件](features/网链资源规划文件.md)。该页面没有“应用规划”操作，本地包也
不会自动建链、改频、分配时隙、修改路由或调用真实分发协议。

### 需求匹配页面

`需求匹配`页包含需求表、匹配结果表、不满足项表、任务级中文建议表和技术依据表。加载内部
`NRM_RESOURCE_DEMAND_V1`文件后可执行批量匹配；表格编辑在提交时创建递增revision，
不会原地覆盖当前修订，旧匹配结果立即失效。

五类明细以二级页签切换，不再同屏挤压。“旧匹配结果失效”指不再可作为当前决策依据；如果只是
实时快照推进，页面仍显示带过期警示的上一轮结果。如果需求集被重新加载、修订或卸载，旧明细会被清除。

每条需求固定输出`PATH / NETWORK_SIZE / DISTANCE / BANDWIDTH / TRAFFIC / DELAY /
PDR / BUSINESS_TYPE`八项检查。适用项显示要求、当前值、裕量、单位和固定原因码；必需
数据缺失时保持无效，不用0代替。验收需求文件明确声明`PARAMETERIZED_MODEL`，因此实时
窗口尚无业务样本时会使用profile容量、PDR和时延做低置信度近似；甲方模块和AFSIM实测
来源不自动降级。显式候选集优先；未提供候选集时，频率、信道、子网和时隙可以从当前
规划allocation的明确字段生成`LOW`置信度建议，站点仍必须有候选路径证据。路由只复用
本次能力结果，页面没有自动应用建议的操作。

### 模型服务门面

v0.12不新增服务管理GUI。开发集成通过`include/nrm/ModelServiceFacade.hpp`的显式方法调用
通信能力、规划校验、规划推演、本地分发包和需求匹配，并使用`ModelServiceContext`携带
schema、requestId、correlationId、softwareVersion和snapshotVersion。DataContainer的
现有页面入口已经复用该门面，页面不重新计算领域逻辑。

`ModelRegistry`只注册`ModelServiceFacade::Descriptor()`描述的NRM模型，查询必须指定精确
版本。外部系统只能通过后续具体`ContractInterfaceAdapter`转换；当前没有甲方协议实现，
完整契约和状态语义见[模型服务门面契约](MODEL_SERVICE_FACADE.md)。

### 预验收状态页面

该页是命令行验收的只读观察入口，不提供启动、停止或重启按钮。显示字段包括执行时间、
总体结果、检查项通过数、固定测试通过数、批准场景通过数、120秒最终快照、Git分支/修订
和Markdown报告路径。状态读取由Warlock侧独立工作线程完成，不占用AFSIM仿真回调；
`NRM_PREACCEPTANCE_STATUS_FILE`可显式覆盖状态文件路径，否则读取
`$NRM_OUTPUT_DIR/preacceptance/latest_status.json`。

重要指标同时保留`valid`、`source`、`confidence`、`sample_time`和`unit`。没有真实RF
结果时，RSSI、SNR和BER在界面显示`—`，JSON中输出`valid=false`，不会用0伪装测量值。

## ⚠️ 当前边界

> 📌 **说明：** 当前四网场景用于验证资源管理器，不代表真实协议栈或装备性能。

- Link-11、卫通和CDL采用通用通信网络近似
- Link-16演示场景尚未切换到JTIDS终端
- 链路来自AFSIM `GLOBAL_TRUTH`全局通信图
- 距离由平台WCS坐标计算
- 窗口PDR目前按网络发送/接收计数，不包含组播预期接收者展开和重传去重
- 利用率依赖有效数据率；通用抽象网络通常只显示吞吐量
- ACK、响应和RTT支持事务关联；无事务标识时使用低置信度估算并明确标源
- 输出线程有界队列深度为128，拥塞时优先保留新快照
- 甲方规划格式、专用校验规则和真实分发协议尚未提供；当前只支持内部格式和本地包
- 现有AFSIM脚本没有安全调用规划服务的入口，因此未创建假的`network_plan_smoke`
- 现有AFSIM脚本也没有安全调用需求匹配服务的入口，因此未创建假的
  `resource_demand_matching_smoke`
- headless mission无法取得Warlock Facade和强类型快照，因此未创建假的模型服务smoke

## 合同补缺功能操作

1. “通信链路”横向滚动查看质量、覆盖裕量、业务类型、子网、协议资源和活动告警。
2. “环境状态”查看作业区域/有效时间与平台姿态；这两项只影响候选链路，不重复修改当前RF结果。
3. “导航状态”查看直接位置误差和水平/垂直/航向1σ精度。直接误差存在时保留原值；缺失时
   使用GNSS、INS或组合导航的低置信度参数。
4. “资源规划”摘要显示空中/地面/联合规划域；加载成员申请JSON后显示协同操作的新修订结果。
5. “需求匹配”执行后显示请求来源、关联编号及同业务历史通过率，六类建议仍只读。
6. 运行`./scripts/check_deployment_contract.sh`生成部署检查；`CUSTOMER_BLOCKED`表示必须由甲方
   提供规范，不是本机失败。

每次运行目录新增`resource_alarms.jsonl`、`demand_feedback.jsonl`和
`planning_coordination.jsonl`。字段、来源与回退规则详见
[甲方接口对齐规范](甲方接口对齐规范与JSON-Schema.md)。

## 🧯 故障排查

### 看不到右侧面板

```text
View → 网络资源管理器
```

如果菜单中没有该项：

```bash
systemctl --user restart nrm-warlock.service
journalctl --user -u nrm-warlock.service -n 100 --no-pager
```

### 面板只有零值

确认标题栏加载的是`four_network_overview.txt`。然后检查：

```bash
pgrep -af '/nrm-remote/opt/afsim/bin/warlock'
```

### 没有输出文件

```bash
WARLOCK_PID=$(systemctl --user show -p MainPID --value nrm-warlock.service)
tr '\0' '\n' < "/proc/${WARLOCK_PID}/environ" | grep NRM_OUTPUT_DIR
ls -la /home/pyh/afsim/network_resource_manager/output
```

启动器默认设置`NRM_OUTPUT_DIR`；也可以手工覆盖该环境变量。
